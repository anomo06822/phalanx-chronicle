# 戰場變化元素路線圖

## 優先順序
1. 元素屬性 + 地形互動
2. 天候系統
3. 戰場陷阱 / 機關 / 事件
4. 羈絆連攜 / 合擊
5. 士氣 / AI stance
6. 可破壞或可轉換地形

## 下一波最值得做的方向
首選是「元素屬性 + 地形互動」。

原因不是它最花俏，而是它最符合目前專案的擴充面：
- 已有 `StatusEffect`，可直接承接燃燒、感電、潮濕、凍結等持續效果。
- 已有 `TerrainType` 與地形加成規則，可把林地、要塞、險地擴成元素反應場。
- 已有 `ScenarioTrigger` / `ScenarioDirector`，可在特定回合或擊破條件下改寫地形與狀態。
- 已有 `SkillVisualEffects` 鉤子，可以為元素技能與地形反應追加明確視覺回饋。

## 各方向的實作建議

### 1. 元素屬性 + 地形互動
- 技能先增加少量標籤，例如 `Fire`, `Wind`, `Water`, `Lightning`。
- 地形先增加少量狀態，例如「可燃」、「潮濕」、「導電」。
- 先做一層簡單反應，不要一次上完整剋屬表。
- 建議第一批反應：
  - 火系命中林地或油地後，地格轉為持續灼燒區。
  - 水系或雨天使單位進入 `Wet`，再被雷系命中時擴大波及。
  - 風系技能可把既有燃燒或煙霧向相鄰格擴散。

### 2. 天候系統
- 先做全場單一天候，不做區域天候。
- 建議第一批只改三種數值：
  - 射程
  - 命中或傷害修正
  - 地形移動成本
- 可用於章節腳本，例如博望坡的火勢蔓延前後切換為強風狀態。

### 3. 戰場陷阱 / 機關 / 事件
- 先從 scenario script 驅動，不要做成全通用編輯器。
- 例子：
  - 可引爆火油點
  - 落石區
  - 橋梁封鎖 / 開啟
  - 回合數觸發的伏兵點

### 4. 羈絆連攜 / 合擊
- 先只支援少量固定角色組合。
- 條件盡量簡單，例如相鄰、同時包夾、同回合先後出手。
- 這條線很適合和 campaign 常駐成長整合，但系統耦合比元素地形高。

### 5. 士氣 / AI stance
- 把 AI 從單純數值貪婪，提升為能切換壓進、防守、撤退、護主等姿態。
- 士氣可以和首領存活、友軍倒下、地形失守連動。
- 這會顯著改變戰局節奏，但需要更多 UI 回饋與調參。

### 6. 可破壞或可轉換地形
- 例如城門、拒馬、橋、火障、冰面。
- 這類系統的戰術價值高，但會碰到 pathfinding、預覽、高亮與 scenario script 的交會點，成本比前幾項高。

## 節奏建議
- 下一輪先做「元素屬性 + 地形互動」的最小版本。
- 目標不是做完整屬性克制，而是做 2 到 3 組可感知、可預覽、可腳本化的互動。
- 若這層跑順，再往上疊天候與場景事件，整體系統會更穩。
